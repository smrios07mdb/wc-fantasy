2 · Data model + resolver contract

Identity is rekeyed ISO2 → clubId. This is the contract, not the data — registry contents ship separately once the DEC-0 licensing-posture sub-item (was INV-10) resolves. The registry must accept crestUrl: null indefinitely.

type ClubId = string                      // stable slug, e.g. 'mer'
type KitVariant = 'home' | 'away' | 'third' | 'gk'

interface KitSpec {
  pattern: 'solid' | 'stripes' | 'hoops'
  body: Hex; pattern2?: Hex               // pattern2 required for stripes/hoops
  sleeves: Hex; collar: Hex
}

interface ClubIdentity {
  clubId: ClubId
  name: string                            // "Meridian SC"
  short: string                           // 3–4 chars, unique (rule §2.1) — feeds monogram + condensed UI
  colors: { primary: Hex; secondary: Hex }
  kits: Partial<Record<KitVariant, KitSpec>>  // home REQUIRED for full
                                          // league-registry entries (D7);
                                          // pool STUBS may omit kits —
                                          // kit-less stubs → neutral kit
  crestUrl: string | null                 // 1:1 SVG/PNG, ≥64px, transparent bg;
                                          // null accepted INDEFINITELY (D7) —
                                          // owned badges are procedural (§4.1),
                                          // no asset URLs exist
  flags?: { plinth: boolean; colorReview: boolean }  // ingest-computed, §10
}

// Sync, from a bundled registry. NEVER throws. The ONLY signature —
// registry lookup is pure; there is no match-scoped overload.
// v2: sizePx is REQUIRED — the crest floor lives in the resolver, not call sites.
// v3: CONFIRMED LOCKED. The sub-16 → monogram floor is registry-blind
// (crestUrl ignored below the floor), and the turn-3 retrofit list is
// DONE across all applied surfaces (canvas 3b → §9).
resolveClubIdentity(clubId: ClubId, sizePx: number): ClubIdentity

// Match-scoped identity is the caller's responsibility — surfaces rendering
// a match pass appearance.clubId as clubId; the resolver is club-agnostic
// to match context. (Who passes what: §7 identity-source table.)

// Fallbacks (in order, per field):
//   sizePx < crest.floor(16) → monogram — ALWAYS; crestUrl ignored (canvas 3b)
//   crestUrl null      → monogram: short on colors.primary, auto-contrast
//                        text — D6a ERRATUM: metric is LUMA
//                        0.2126r + 0.7152g + 0.0722b on raw sRGB (0–1);
//                        > .55 → #10141C, else #FFFFFF. (Mocks already
//                        comply, source-verified; "relative luminance"
//                        wording deleted.)
//   monoText (D6b)     → resolver-derived from sizePx: 3 chars ≥24px,
//                        2 chars <24px. Call sites LOSE the choice —
//                        the short/mono2 free pick is removed.
//   unknown clubId     → neutral: name "Unknown club", short '—',
//                        dashed 50% circle, neutral slate kit (dashed outline)

2.1 · Short codes at 36 clubs — collision rule (mechanical)

// Production pool is 36 clubs (Decision (b)); the placeholder registry
// proves 12 + 24 layout stubs (canvas 3a). 3-char shorts WILL collide at 36.
// Deterministic — no product call.

- Validation: shorts unique per registry, checked at registry BUILD.
  CI fails the bundle on collision — collisions are never a runtime state.
- Derivation on collision:
  1. the lexicographically-first clubId keeps its 3-char short; every other
     collider extends to 4 chars using the next significant character of
     `name` (skip spaces + generic tokens FC/SC/CF/AC/FK/SK/SV/XI/United):
     MER / MERD
  2. still colliding → 4th char becomes a digit 2–9 by clubId order: MER2
  3. pathological (>9 colliders) → crest-only + full name; short renders
     '—'. Never ship an ambiguous short.
- Layout: every short slot reserves 4ch in the mono font, so 4-char shorts
  never reflow or truncate a surface.

// Where the short is load-bearing vs. decorative (v2 — floor-aware)
- Short is SOLE identity (must render the full, possibly 4-char short):
  mobile bracket rows, condensed row sublabels (<420px), opponent slots
  ("@ OST") — those slots sit under crest.floor, so the roundel is a
  monogram and the SHORT is the identifier.
- Crest alone carries identity at ≥18px ONLY when crestUrl is set (real
  silhouette). A monogram is a hint, not an identifier — any monogram-only
  context keeps name or short in the same row.
- <16px: the crest asset never renders (crest.floor) — monogram + adjacent
  short carry identity together.

4 · Crest

<Crest clubId size={24} dim? />

// No matchId prop — the calling surface selects clubId per the §7
// identity-source table and passes the result.

- size < crest.floor(16) → monogram, resolver-enforced (§2). The component
  dev-asserts on sizes below 12 — nothing in the system renders there.
- crestUrl → <img src alt="{club.name} crest"> — raw asset, NO circle crop,
  no bg plate; asset owns its silhouette. Reserve a square size×size slot.
- plinth (canvas 3c, LOCKED): registry flags.plinth → wrap in crest.plinth
  roundel so dark marks don't sink into surface.base (#0A0D12 pin, §1 —
  the sink check runs against the page token, not the mock floor).
  Ingest-computed (§10), never a per-surface decision. Monograms exempt
  at every size (mono.ring carries the edge ≥16; sub-16 discs ride their
  fill — v5/MG-2), incl. the 40px 6c match header.
- dim (v2, canvas 4a): opacity = max(kit.dim, crest.dimFloor) — the crest
  stops dimming at .55 while kit + text follow the token.
- fallback → monogram roundel: bg colors.primary, mono.ring (≥16px ONLY —
  v5/MG-2, matches all mocks + t12), text short (3 chars ≥24px, 2 chars
  <24px — D6b), auto-contrast fg (LUMA metric, §2 D6a), font 700, ~size×0.34.
- unknown → dashed 50% circle, no text; alt "Unknown club".
- onError of the img swaps to monogram at runtime (bad/missing asset ≠ broken UI).
- Never emoji, never a flag. Decorative repeats (same row) → alt="".
